### Supabase runtime database role

The migrations create all application tables in `public` and use UUID primary keys; they currently create no sequences. Runtime SQL uses ordinary Prisma CRUD plus a pgvector cosine-distance search. Before creating Render services, connect to the Supabase SQL Editor as `postgres`, replace the password placeholder below with a unique generated password, and run this once. The public app tables do not exist until the first migration, so the default privileges below grant the needed rights as the migration user creates them. Do not save the replaced SQL as a reusable snippet. This role has no database/schema creation, role-management, superuser, replication, or RLS-bypass privileges; migrations continue to use the separate `postgres` URL.

```sql
CREATE ROLE supportiq_runtime
  LOGIN
  PASSWORD 'REPLACE_WITH_A_UNIQUE_LONG_PASSWORD'
  NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS NOINHERIT;

GRANT CONNECT ON DATABASE postgres TO supportiq_runtime;
GRANT USAGE ON SCHEMA public, extensions TO supportiq_runtime;

-- The app casts retrieved embeddings to vector and runs the <=> cosine operator.
GRANT USAGE ON TYPE extensions.vector TO supportiq_runtime;
GRANT EXECUTE ON FUNCTION extensions.cosine_distance(extensions.vector, extensions.vector)
  TO supportiq_runtime;

-- Future objects created by the migration login (postgres) remain usable by the app.
ALTER DEFAULT PRIVILEGES FOR ROLE postgres IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO supportiq_runtime;
ALTER DEFAULT PRIVILEGES FOR ROLE postgres IN SCHEMA public
  GRANT USAGE, SELECT ON SEQUENCES TO supportiq_runtime;

ALTER ROLE supportiq_runtime SET search_path = public, extensions;
```

All current IDs are UUIDs, so there are no current sequences; the sequence default privilege covers a future migration that adds one. The app only needs the `vector` type and cosine-distance function for its present retrieval query. Default table privileges also give the runtime role access to Prisma's `_prisma_migrations` ledger when it is first created. After the first migration, remove that unnecessary access by running `REVOKE ALL ON TABLE public."_prisma_migrations" FROM supportiq_runtime;` as `postgres`. Keep the migration URL on `postgres`, since Prisma migration deployment must create and alter schema objects.

Use the exact shared **Session pooler** host copied from Supabase's Connect dialog. Replace the angle-bracket placeholders privately, and URL-encode reserved characters in each password. Both URLs use port `5432` and require TLS:

```text
DATABASE_URL=postgresql://supportiq_runtime.<PROJECT_REF>:<URL_ENCODED_RUNTIME_PASSWORD>@<SESSION_POOLER_HOST>:5432/postgres?sslmode=require
MIGRATION_DATABASE_URL=postgresql://postgres.<PROJECT_REF>:<URL_ENCODED_DATABASE_PASSWORD>@<SESSION_POOLER_HOST>:5432/postgres?sslmode=require
```

## Free-tier costs and limitations

The selected baseline is **$0/month** while all accounts remain within the named Free plans and the demo stays under their quotas. Render Free web instances sleep after 15 idle minutes and typically take about a minute to wake. They share a 750 instance-hour monthly allowance across the workspace; two continuously active services consume it in roughly 15.6 days. They have ephemeral disks, so uploads must go to private Supabase Storage. At the free bandwidth ceiling Render suspends services for the rest of the month if no payment method is added; do not add one. Free services have no private network, no SLA, and limited resources. Render blocks outbound SMTP ports 25, 465 and 587. The API proxy timeout is configured at 135 seconds; browser safe GET requests retry only transient 502/503/504 wake-up responses with a bounded delay. Mutations are not automatically retried, avoiding accidental duplicate ticket replies or sends. [Render Free](https://render.com/docs/free), [web service behavior](https://render.com/docs/web-services), [first deploy without a card](https://render.com/docs/your-first-deploy).

Gemini calls have no assumed charge while the project remains Free and billing stays disabled, but free quotas are limited and variable; there is no guarantee of availability. Supabase Free has finite database/storage/egress and may pause/delete under its published policies. Backups and exports are manual. Render and Supabase may change their free plans. Check each dashboard's plan, usage and limits before opening the demo, and do not add payment methods or upgrade. [Supabase Free plan](https://supabase.com/pricing), [Gemini billing](https://ai.google.dev/gemini-api/docs/billing).

There is no custom domain. Provider URLs are used. Two live services may consume the Render allowance faster while active; sleeping is an accepted tradeoff. The frontend's first API-backed request can cold-start the API as well as the web service. A public request may show a temporary wake-up message; the app must not replay non-idempotent writes. If Gemini quota is exhausted, the API returns a temporary-unavailability response and the UI explains that drafting is temporarily unavailable. No canned answer or mock provider is used in the public build.

## Runtime database readiness diagnostics

`GET /health/ready` runs `SELECT 1` through the runtime `DATABASE_URL`. On failure, the response stays generic (`Database is unavailable`) and the API emits a `database_readiness_failed` warning with the matching request ID, an allowlisted category, and—only when recognized—an allowlisted driver/Prisma error code. It never logs the exception message or connection URL. Categories distinguish authentication, TLS, permission, missing database, connection, timeout, capacity, shutdown, and unknown failures. Do not disable certificate verification to resolve a TLS category.

The production API build runs `prisma migrate deploy` using the separate `MIGRATION_DATABASE_URL` before starting the service. A successful runtime readiness check does not prove that migrations completed, and a failed runtime connection does not establish whether the build-time migration connection succeeded. Check the API deployment build log for the migration command's successful exit, then inspect Supabase's `public."_prisma_migrations"` table read-only before seeding. The runtime connection should use the dashboard-provided shared Session pooler, port 5432, `sslmode=verify-full`, the root certificate downloaded from that project's Database Settings, and the least-privilege `supportiq_runtime` role; keep the migration URL separate. Supabase documents that `require` encrypts traffic but does not itself verify the server certificate or hostname. Never paste either URL into logs, chat, or screenshots.

To test a hosted runtime URL locally without printing it, download that project's CA certificate from Supabase **Database Settings → SSL Configuration** and keep it outside the repository. In an interactive terminal, run `pnpm --filter @supportiq/api db:check:runtime --prompt`; the script prompts with terminal echo disabled, even when `.env` contains a development URL. Enter a URL with `sslmode=verify-full` and `sslrootcert` set to the downloaded certificate path. The script uses the same Prisma Client and `PrismaPg` adapter as the server, and executes only `SELECT 1`. If the adapter reports a generic TLS category, a narrowly scoped node-postgres probe uses the same URL and TLS verification to recover an allowlisted underlying TLS code; it also executes only `SELECT 1`. It prints no URL, raw exception, or certificate contents. It performs no migration, reset, seed, or other write. Supabase's [database connection guide](https://supabase.com/docs/guides/database/connecting-to-postgres) and [SSL enforcement guide](https://supabase.com/docs/guides/platform/ssl-enforcement) document the certificate download and `verify-full` requirement.

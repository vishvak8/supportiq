# $0 public portfolio demo plan

Updated **2026-10-18**. The user approved free-only deployment preparation and launch. No hosting account has been connected, resource created, billing enabled, or deployment performed yet. A local API call using the locally configured Gemini key succeeded with synthetic data; it does not verify the AI Studio project's billing linkage or effective quota. The public demo is a low-traffic portfolio demonstration, not a production service or an availability promise.

## Recommended architecture

Use two Render Free Node web services in Singapore: Next.js at `supportiq-web-free.onrender.com`, and NestJS at `supportiq-api-free.onrender.com`. Next.js rewrites `/api/*` server-side to the API using `API_INTERNAL_URL`; the browser stays on the web origin. Render Free has no private service networking, so the API has a public provider URL. It still requires the exact configured web `Origin`, CSRF token, signed secure session cookie, active membership, and tenant-scoped authorization. API keys and storage credentials stay in the API environment. Do not use the laptop's Ollama endpoint remotely.

Use Supabase Free in Singapore for persistent PostgreSQL with pgvector and a private Storage bucket through its S3-compatible endpoint. Create a private bucket and a server-only S3 key. Disable Supabase Data API because the app uses Prisma through its server-side database connection, not Supabase's browser API. Render Free services are IPv4-only, while Supabase's direct database endpoint on Free is IPv6-only, so both `DATABASE_URL` and `MIGRATION_DATABASE_URL` must use the Supabase shared **session** pooler on port 5432 with SSL required. Use distinct least-privilege runtime and migration database roles; enable the `vector` extension in Supabase before the app's first migration if the migration role cannot create extensions. Do not select Supabase's paid IPv4 add-on or transaction pooler. The session pooler is the supported IPv4 path for a persistent backend and supports prepared statements; the actual first migration will be verified before seeding. Supabase Free currently includes 500 MB database, 1 GB file storage, 5 GB uncached and 5 GB cached egress, shared 500 MB RAM compute, two active free projects, and no automatic backups. A project with low activity can pause after one week; it can be resumed within the documented one-year window. Export the database and storage metadata regularly because the free plan does not include automatic backups. [Supabase pricing](https://supabase.com/pricing), [pausing](https://supabase.com/docs/guides/platform/free-project-pausing), [backups](https://supabase.com/docs/guides/platform/backups), [S3 storage authentication](https://supabase.com/docs/guides/storage/s3/authentication), [Prisma connection guidance](https://supabase.com/docs/guides/database/connecting-to-postgres).

Select Gemini only on the public deployment. Use `gemini-3.5-flash-lite` for generation and `gemini-embedding-2` with `outputDimensionality: 768` for embeddings. Google's current model guidance restricts Gemini 2.5 access for new projects, so the earlier proposed 2.5 Flash-Lite tag is unsuitable for a newly created demo project. The 3.5 Flash-Lite standard tier and Embedding 2 text inputs are listed as free. The embedding model supports 768 dimensions and the existing `vector(768)` schema; it is a separate embedding space from Nomic or any other provider. A model/provider change requires re-embedding every indexed document, even when dimensions match. Local development keeps Ollama as the default provider. Model tags remain configurable with `GEMINI_GENERATION_MODEL` and `GEMINI_EMBEDDING_MODEL`. Generation is capped to bounded context/output and 45 seconds, with one retry for transient network/server failures; quota responses do not retry or fall back. Embeddings are sent in batches of at most 50. Every retrieved source is filtered by organisation and current document generation, and the resulting citation IDs are revalidated before a persisted draft is shown. Sending remains a separate agent action.

Gemini API pricing currently lists both selected models on the Free tier. This means a request may be throttled or become unavailable; it does **not** promise a fixed quota or uptime. Google sets RPM, TPM and RPD per project/model, can change those limits, and exposes the account's effective values in AI Studio. The app adds persistent limits of 20 drafts globally/day and 2 per user/day; 4 knowledge article/upload/update/retry operations globally/day and 1 per user/day; and 60 searches globally/day and 10 per user/day. Uploads are limited to 2 MiB and extracted/indexed text to 25,000 characters. Ticket creation, messages, attachment uploads and downloads also have persistent global and per-user quotas. These conservative limits still need to be aligned with the specific AI Studio quota shown for the configured project. Google AI Studio/API usage remains subject to provider throttling beyond our app caps. Free-tier content can be used by Google to improve products and may be reviewed by human reviewers. The interface discloses this before AI use and knowledge entry and instructs users to use synthetic content only. Never put real customer, personal, confidential, or sensitive data in the public demo. [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing), [model quotas](https://ai.google.dev/gemini-api/docs/rate-limits), [terms and free-tier data use](https://ai.google.dev/gemini-api/terms), [generation model](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite), [embedding model](https://ai.google.dev/gemini-api/docs/models/gemini-embedding-2), [embedding task types](https://ai.google.dev/gemini-api/docs/embeddings).

Create a Google AI Studio account, meet its age requirement (18+), use a supported country (Australia is listed), accept the Gemini API terms, and create/use a project that remains on the Free tier with **no billing account linked**. Create the key in AI Studio and set it only as Render's `GEMINI_API_KEY` secret after deployment approval. Do not enter it in chat, source control, browser code or a public issue. Do not enable billing or configure any paid fallback. Confirm the configured model tags and effective per-model quotas in AI Studio before opening the demo. Google documents that connecting a billing account can move a project to paid service; Free-tier rate limits are account/project specific. [API key setup](https://ai.google.dev/gemini-api/docs/api-key), [billing](https://ai.google.dev/gemini-api/docs/billing), [supported regions](https://ai.google.dev/gemini-api/docs/available-regions).

Disable outbound email on the hosted demo (`MAIL_MODE=disabled`); show that invitations and recovery email are unavailable there. No domainless email provider is assumed. Local development continues to use Mailpit. This preserves team and password-reset code paths locally without sending mail from a public demo.

Seed the public demo explicitly with `pnpm db:seed:demo` after migrations. It creates one organisation with a demo agent and customer, a synthetic invoice-download ticket and synthetic invoice/help articles, but no shared administrator. It refuses to run unless explicitly enabled and a password has been configured. Use a unique high-entropy `PUBLIC_DEMO_PASSWORD`, share it only through the demo instructions after deployment approval, and never grant administrator access to anonymous visitors. The seed is idempotent and does not reset existing account passwords. Rerun it only when intentionally restoring its synthetic demo records. The API worker resumes pending ingestion jobs on process start and retries transient failures with backoff. Render's service sleeps after 15 minutes without inbound traffic; a queued document may therefore wait for the next API wake. A free Supabase project can pause after a week of low activity and must be resumed before requests can work.

## Free-tier costs and limitations

The selected baseline is **$0/month** while all accounts remain within the named Free plans and the demo stays under their quotas. Render Free web instances sleep after 15 idle minutes and typically take about a minute to wake. They share a 750 instance-hour monthly allowance across the workspace; two continuously active services consume it in roughly 15.6 days. They have ephemeral disks, so uploads must go to private Supabase Storage. At the free bandwidth ceiling Render suspends services for the rest of the month if no payment method is added; do not add one. Free services have no private network, no SLA, and limited resources. Render blocks outbound SMTP ports 25, 465 and 587. The API proxy timeout is configured at 135 seconds; browser safe GET requests retry only transient 502/503/504 wake-up responses with a bounded delay. Mutations are not automatically retried, avoiding accidental duplicate ticket replies or sends. [Render Free](https://render.com/docs/free), [web service behavior](https://render.com/docs/web-services), [first deploy without a card](https://render.com/docs/your-first-deploy).

Gemini calls have no assumed charge while the project remains Free and billing stays disabled, but free quotas are limited and variable; there is no guarantee of availability. Supabase Free has finite database/storage/egress and may pause/delete under its published policies. Backups and exports are manual. Render and Supabase may change their free plans. Check each dashboard's plan, usage and limits before opening the demo, and do not add payment methods or upgrade. [Supabase Free plan](https://supabase.com/pricing), [Gemini billing](https://ai.google.dev/gemini-api/docs/billing).

There is no custom domain. Provider URLs are used. Two live services may consume the Render allowance faster while active; sleeping is an accepted tradeoff. The frontend's first API-backed request can cold-start the API as well as the web service. A public request may show a temporary wake-up message; the app must not replay non-idempotent writes. If Gemini quota is exhausted, the API returns a temporary-unavailability response and the UI explains that drafting is temporarily unavailable. No canned answer or mock provider is used in the public build.

## Cleanup

1. Put the web demo into maintenance mode or remove its public service. Revoke the Gemini key in AI Studio and remove the API key from service secrets.
2. Export any desired synthetic demo records. Delete both Render services and their environment secrets.
3. Delete the Supabase bucket and its objects, revoke the S3 credential, export data if needed, then delete the Supabase project. Deletion is permanent; the Free plan does not supply automatic backups.
4. Confirm provider dashboards show no active services/projects, no billing account attached to Gemini, no payment method added, and no residual resource usage.
